=== Root Cause

- Reservation repos exist (lithoglyphdb, gnpl, glyphbase) but content still in `nextgen-databases/lithoglyph/`
- Prior lith monorepo was unauthorised agent fabrication (corrected in #44)
- GNPL (GQL-dt query language) and LithoglyphDB (store) were entangled — design decision needed, not mechanical move
- Coordination repo contained implementation (819 + 713 files) — LLMs kept adding per-database content because code lived here, no top-level guardrail

=== Fix — At Source — Design Decision (Not Mechanical)

- Created `docs/migration/LITHOGLYPH-GNPL-DISENTANGLEMENT.adoc` (2026-09-25) documenting:
  - GNPL vs LithoglyphDB semantic separation (table: purpose, layer, proof, API)
  - Why separate (LithoglyphDB can exist without GNPL, GNPL can exist without LithoglyphDB, proof obligations differ, public language is GNPL)
  - What was superseded, not migrated: `lithoglyph/core-factor/gql/` — runtime counterpart to GQLdt compile-time proofs, replaced by typed narration layer lowering to GQLdt
  - Extraction table: was → now, files, status (lithoglyph 819 DONE 2026-07-27, glyphbase 130 DONE, gnpl 125 DONE PR #4, core-factor/gql/ NOT MIGRATED)
  - History preservation: `split-history/lithoglyph` 819 files 68 commits, `split-history/verisimdb` 713 files 124 commits, `_split_gnpl` branch, never prune
  - Glyphbase own repo rationale (UI vs core DB concerns, AffineScript TEA per migration plan)
  - Enduring guards: upstream placement guard + block-db-writes + 0-AI-MANIFEST.a2ml + CLAUDE.md; downstream owning repos; cross-repo wiring REGISTRY.adoc, TOPOLOGY.adoc, EXPLAINME.adoc, STATE.a2ml
  - Acceptance criteria checklist (all 5 DONE)
  - Note on naming: issue says `lithoglyphdb` but actual canonical is `lithoglyph` per REGISTRY.adoc and extraction PR #4 — reservation `lithoglyphdb` superseded

== Issue #53 — K9 Pedigree + Trusted-Base

=== K9 Pedigree — Root Cause

- File `verisimdb/connectors/test-infra/deploy.k9.ncl` used `let component_pedigree = { metadata = { name = "verisimdb-test-infra", ... } } in { pedigree = component_pedigree, ... }` — valid Nickel but early validator could not follow let indirection
- Validator fixed to handle one-hop let: `pedigree_alias=$(sed -nE 's/^[[:space:]]*pedigree[[:space:]]*=[[:space:]]*([A-Za-z_][A-Za-z0-9_]*)...')` + treat `let <alias> = {` as block opener
- File removed from this repo 2026-08-03 when verisimdb extracted

=== Fix — At Source — Validator

- `validate-k9.sh` now resolves `let` indirection (upstream fix in `hyperpolymath/standards` governance bundle + local copy)
