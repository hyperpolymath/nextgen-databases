== Issue #53 Summary

Two pre-existing, repo-internal findings flagged during 2026-06 estate CI-health work
(hyperpolymath/hypatia#464), explicitly out of scope for central `actions/cache` + scanner-compile fixes:

1. K9 pedigree — missing `metadata.name` in `verisimdb/connectors/test-infra/deploy.k9.ncl` — fails "Pedigree block missing 'name'". In `standards/k9-svc/pedigree.ncl`, `Metadata.name | String` is only metadata field with no default, so mandatory. Fix: add `metadata.name`; per canonical `standards/k9-svc/pandoc/container/deploy.k9.ncl`, ideally also `metadata.version` + `validation.pedigree_version` and leash level `trust_level`/`security_level` ∈ `'Kennel | 'Yard | 'Hunt` (shell-running deploy.k9.ncl is `'Hunt`).

2. `governance / Trusted-base reduction policy` red — undocumented soundness-relevant escape hatch in proof-bearing file. Disposition per-repo — discharge, budget (`// TRUSTED:`), axiom (`// AXIOM:`), or dated entry in this repo's `docs/proof-debt.md`.

Refs: hyperpolymath/hypatia#464, hyperpolymath/nextgen-typing#69.

== Root Cause Analysis

*K9 pedigree:*

- File `verisimdb/connectors/test-infra/deploy.k9.ncl` existed in monorepo era (verisimdb still in this repo)
- It used `let component_pedigree = { metadata = { name = "verisimdb-test-infra", ... } } in { pedigree = component_pedigree, ... }` pattern — valid Nickel, but early version of `validate-k9.sh` could not follow `let` indirection, so reported missing name even though name was present at line 23
- Validator fixed in later version (see comment in `validate-k9.sh` about pedigree_alias handling) — now correctly resolves one-hop `let` indirection
- File removed from this repo 2026-08-03 when verisimdb extracted to `hyperpolymath/verisimdb` (713 files)

*Trusted-base:*

- Proof-bearing files (`.idr`, `.lean`, `.agda`) lived in `verisimdb/`, `typeql-experimental/`, `verisim-modular-experiment/` in monorepo era
- No `docs/proof-debt.md` existed to document `// TRUSTED:` / `// AXIOM:` / `believe_me` usage
- Governance workflow flagged undocumented escape hatch but no disposition path existed in this repo

== Foundational Fix (Upstream/Downstream, Enduring)

=== Upstream — Validator Improvement (already in `validate-k9.sh`)

The K9 validator now handles `let` indirection:

[source,bash]
----
# From validate-k9.sh — resolves one-hop let binding
pedigree_alias=$(sed -nE 's/^[[:space:]]*pedigree[[:space:]]*=[[:space:]]*([A-Za-z_][A-Za-z0-9_]*)[[:space:]]*,?[[:space:]]*$/\1/p' "$file" | head -1)
# If pedigree = <identifier> names a binding, treat let <identifier> = { as block opener too
----

This fix is upstream in `hyperpolymath/standards` governance bundle (reusable workflow) and local copy in `.github/hooks/validate-k9.sh`. It prevents false positives on valid Nickel `let` patterns.
